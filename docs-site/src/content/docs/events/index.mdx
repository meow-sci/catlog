An **event** is one thing catlog wrote down. Every event has a type — a name like
`vehicle.impact` or `kitten.tumble` — and that name is unique across the whole
catalog. There are 25 of them.

<LinkCard
  title="Browse every event"
  href="/catlog/events/browse/"
  description="All 25 in one filterable table, searchable by name, field or board."
/>

## How to read an entry

Every event on these pages carries the same blocks.

| Block                           | What it tells you                                                                                  |
| ------------------------------- | -------------------------------------------------------------------------------------------------- |
| **What causes it**              | The thing in the game that produces the event.                                                     |
| **Where the numbers come from** | Which readings on your vehicle, kitten or roster the values are taken from.                        |
| **What stops it firing**        | Thresholds, dead bands and minimum intervals — why a thing you did might not have been recorded.   |
| **What it feeds**               | The leaderboards this event moves. Several events feed nothing; they are recorded and kept anyway. |
| The field table                 | Every value stored, its unit, and what it means.                                                   |

## You do not have to record all of them

Almost every type here is optional. You can switch any of them off in the mod's
settings, individually, and the rest of the mod carries on unchanged — the cost
is that you stop appearing on whatever that type feeds, or lose the catalogue
features only `system.body` supplies. Six cannot be switched off, and they are
marked **always on** wherever they appear on this site.

## The two kinds of event

<CardGrid>
  <Card title="Something happened" icon="rocket">
    The game tells catlog directly, at the moment it happens: a stage fired, a dock completed, a
    vehicle came apart, a kitten stepped outside. These are exact — there is no sampling and nothing
    to miss.
  </Card>
  <Card title="Sampled in the background" icon="information">
    catlog looks at every vehicle twice a second and compares this reading against the last.
    Crossing into an atmosphere, achieving orbit, changing sphere of influence, touching down on a
    surface, a kitten going over, and all the flight telemetry work this way.
  </Card>
</CardGrid>

A sampled event can be missed if the change happens and reverses inside half a
second. Most of them have deliberate dead bands and minimum intervals on top of
that, so skimming a boundary produces one crossing rather than forty.

## Every event carries

|                      |                                                                          |
| -------------------- | ------------------------------------------------------------------------ |
| a unique id          | so an event that arrives twice is counted once                           |
| its type and version | the version changes whenever the shape of that event changes             |
| a flight             | which vehicle's flight it belongs to, where that makes sense             |
| a session            | one per time you start the game or load a save                           |
| a career             | which career it belongs to                                               |
| a game clock reading | seconds since that career began                                          |
| a wall clock reading | recorded, but **never trusted** — the server stamps its own arrival time |

<Aside type="tip" title="A note on units">
  A field name ending `_ms` means **metres per second**. A leaderboard whose unit is shown as `ms`
  means **milliseconds**. They are genuinely different things, and the overlap is unfortunate.
</Aside>
