If a number you expected is missing, it is one of the rules on this page. They are
all here — starting with the one that is not a rule at all.

## You may have switched it off

**A board can be legitimately empty because you told catlog not to record what
feeds it.** Almost every kind of event is optional: you can switch it off in the
mod's settings, and from then on the mod stops producing it, nothing is sent, and
the server never learns there was anything to know. There is no other source, so
the board simply has nothing of yours to rank.

This is the first thing to check when a number is missing and none of the rules
below seem to apply — particularly if you changed a setting months ago and forgot.
The mod's status window has a row that says whether anything is switched off, and
lists what.

**Five kinds of record cannot be switched off**, and setting them to off is
ignored: a flight beginning, a flight ending, a flight being marked, a session
starting, and losing a kitten. Those are the ones that decide what a run is
_worth_ rather than what it contains — the marking one in particular is the only
thing that says a run was assisted, so without it every rule in the next section
would be optional too.

## The flag rule

Five things mark a flight, and **a marked flight scores nothing at all** — not the
record it was setting, not the counters, not the activity feed, not the raw event
views.

| Flag            | Raised when                                                                               |
| --------------- | ----------------------------------------------------------------------------------------- |
| `teleport`      | You teleported a vehicle by a player command, including the Set Orbit debug window.       |
| `refuel`        | The vehicle's consumables were refilled.                                                  |
| `resource_edit` | The vehicle's consumables were drained.                                                   |
| `console`       | The terminal's `destroy` command was used on the vehicle.                                 |
| `tuning`        | The kitten locomotion tuning differs from stock (the tumble speed gate is 6.5 m/s stock). |

Three details:

- **A flag catlog does not recognise still excludes.** If a future version adds a
  sixth flag and an older server sees it, that flight is excluded anyway. Failing
  the other way would make every new flag a loophole for as long as servers lag
  behind mods.
- **A session-wide flag sticks to everything.** Changing the tumble tuning is not
  attached to one vehicle, so it applies to every flight open at the time and every
  flight started afterwards that session.
- **A few boards are exempt**, and it is structural rather than a judgement call.
  Distance Travelled, Furthest-Travelled Kitten and Most Missions Flown come from
  your roster totals, which are not attached to any flight, so there is nothing to
  flag. Longest Spacewalk is the same: the game tells catlog a spacewalk ended
  without saying which vehicle it ended at. Spacewalks is a half-exception — the
  rule applies when catlog could tell which vehicle the kitten stepped out of, and
  not when it could not. Fixing any of these would mean the mod attaching those
  moments to a flight, which is not something the server can do for it.
  **Kitten Tumbles was one of these and no longer is**: a tumble now belongs to the
  kitten's own spacewalk flight, so changing the tumble tuning excludes those
  tumbles, which is exactly what that mark was always for.

## Impact rules

An impact only becomes a **Biggest Lithobrake Survived** or **Biggest Bang
Survived** candidate if all of these hold. The two boards score the same crashes
by design, so they can never disagree about which ones counted:

- The vehicle still existed a frame later.
- You did not destroy it yourself immediately afterwards — that counts exactly the
  same as the impact having destroyed it.
- It was not the launch pad.
- Somebody was aboard.
- It was not within 5 seconds of a teleport. The game suppresses impact effects
  there, and that is not a landing.
- The flight is not flagged.

<Aside type="caution" title="Why the one-frame wait exists">
  The game applies every impact for a frame before it applies any destruction, and a destruction you
  asked for lands later still. Deciding "did it survive" in the same frame would have called every
  fatal crash a survival.
</Aside>

## Peak-g and max-q rules

A peak-g or max-q reading counts only when the game actually computed one. It does
that while a vehicle is under full physics; on rails or in freefall there is no
reading at all, and catlog leaves the field out rather than writing a zero.

Writing zeros would have filled both boards with entries from vehicles that were
not being simulated.

Both figures come off the same structural-load reading, so they share every rule
including the recovered-flight one below. **Highest Altitude deliberately does not
share it.** An altitude is a position rather than a physics result — it is always
readable — so a probe that never came home still holds whatever height it reached.

**Height above the ground follows the same leave-it-out rule**, for a different
reason: in orbit there is nothing underneath you to measure against, so a window
spent up there carries no such reading at all and scores nothing on Lowest Pass.
That figure is also folded over only the samples that had a ground reading, so it
describes fewer samples than the rest of the window does.

## Missing is not zero

Three things catlog records can simply be unavailable: your height above the
ground, your latitude and your longitude. When the game cannot answer, **the value
is left out of the record entirely.** It is never written as zero.

That is not fussiness. Zero is a real answer to all three questions. A ground
clearance of zero means you are on the ground. A latitude of zero is a specific
place — a point in the ocean south of Ghana — and so is a longitude of zero. A
zero standing in for "catlog could not tell" would be a **wrong** record rather
than a missing one, and a wrong record is the harder of the two to notice.

It is the same rule peak g has always followed, applied to the newer readings.

## Zero rules

Several boards refuse a value of exactly zero, and it is always for the same
reason: **zero is what a reading catlog could not take looks like.** A mass of
zero is an unreadable vehicle, not a weightless one; an eccentricity of zero is a
figure that was never written, not a perfect circle; a spacewalk of zero seconds
is a start time that could not be read.

On the five boards where the **smallest** number wins — Lowest Stable Orbit,
Roundest Orbit, Softest Touchdown, Softest Landing and Lowest Pass — this matters
more than tidiness. A zero there would be an unbeatable record held by a failed
measurement, and no real flight could ever take it back.

Two of those five refuse a zero for a reason worth spelling out:

- **Softest Landing.** A real touchdown is never at exactly zero metres per second
  — catlog looks twice a second and the vehicle is still settling — so a flat zero
  is a measurement that did not come out, and on a board where gentlest wins it
  would be untouchable.
- **Lowest Pass.** Zero is where a vehicle sitting on the ground reads. Every
  flight ever flown would tie on it before leaving the pad, so the board takes
  only readings above zero. A landing is not a pass; Softest Landing is the board
  for arriving.

Softest Touchdown and Softest Landing both add one more of these. They need to
know you were genuinely off the ground beforehand, and "catlog could not tell what
you were doing" is not the same answer as "you were in freefall" — so an
unreadable state on either side of the change is refused rather than accepted as
airborne.

## Rebuilding, and the answers that change

Boards are normally updated as events arrive. Sometimes the whole set is discarded
and recomputed from the log — after a purge, or a schema change, or when a fold
gains a rule. **A rebuild can produce a different answer, and that is intended.**

Two rules cannot be evaluated live, because they depend on how a flight _ended_
and the events are still arriving one at a time:

1. **An impact within 2 seconds of a kitten being lost is dropped.** Live, catlog
   cannot know a kitten is about to be lost. This applies to both impact boards.
   The rule needs to know _whose flight_ the kitten died on, and losses only began
   carrying that — so a crash that killed a kitten now stops being a survived
   landing, which is what this rule always said it did.
2. **A peak-g or max-q reading only counts if the flight ended recovered.** Live,
   the flight may still be in progress. This is the widest of them — every flight
   that ended destroyed or despawned loses both rows on a rebuild.

One is about ordering rather than knowledge:

3. **A flag that arrived late.** Live, the events folded before the flag reached
   the server had already scored. A rebuild sees the completed flight and drops
   them all.

And one is about catlog itself changing:

4. **A board that did not exist when your flight happened.** Every event catlog has
   ever received is kept, including the ones nothing was reading at the time. When
   a new board is added, the events that would have fed it are already in the log —
   but the live path has long since gone past them, so it can only score what
   arrives from now on. A rebuild replays the whole log through the new rules and
   fills the board in from your actual history.

   This is not hypothetical: the boards for atmospheric entry, spacewalks, engine
   ignitions and flameouts were added to a log that had been quietly collecting
   those events all along. Until a rebuild runs, they show only what has happened
   since.

5. **A board that reads a figure your older flights never recorded.** This is the
   sharper version of the case above, and it applies to the newest boards.
   **Heaviest Payload To Orbit**, **Most Stages Built** and **Lowest Pass** each
   read something the mod did not use to send — what the vehicle weighed as it
   made orbit, how many stages it was built with, and how high you were above the
   ground. Flights recorded before that change carry no such figure, so they read
   as zero, and all three boards refuse a zero. **They score nothing for your
   older flights, and a rebuild does not rescue them** — the number was never in
   the log to begin with. What a rebuild does fix is everything recorded since.

   **Softest Landing** and **Landings** are simpler: landing was not a thing
   catlog recorded at all before, so those two have no history whatsoever and
   start from your first flight with the new mod.

Rebuilding is always the more correct answer: it is the one computed with the whole
story in hand.

## Moderation

A banned player disappears from every public surface at once. Their rows still
exist in the derived tables, but nothing can render them, because every handle is
resolved from one directory and a banned player is not in it.

- **A ban closes the gap rather than leaving a hole** — ranks are positions among
  the rows you can see.
- **Player counts still include them.** "412 players on this board" is the honest
  row count.
- **An unknown, retired and banned handle all return the same "not found"**,
  deliberately: anything else would be a way to test whether somebody was banned.

## What catlog will never check

Anti-cheat here is capped, on purpose. catlog assumes stock game data and stock
settings, and goes no further. Specifically it will never do physics-plausibility
scoring, quarantine runs pending review, compute suspicion scores against other
players, or operate a report queue.

Those were all considered and settled as never-to-be-built. The reasoning is that
each one converts a hobby leaderboard into a tribunal, and every one of them
produces false positives against players who did nothing wrong.

What catlog does instead is narrow and checkable: it detects the five specific
actions above, at the exact point the game performs them, and excludes those
flights.
